# Архитектура

VideoDownloader разделён на небольшой UI и независимые слои предметной логики.

```text
PySide6 widgets
    │ signals / immutable models
    ▼
AppController + background workers
    ├── SettingsService ── JSON in %LOCALAPPDATA%
    ├── ToolManager ───── download / SHA-256 / atomic install
    └── YtDlpService + DownloadExecutor
            │ argument vector, no shell
            ▼
        yt-dlp.exe ─────── ffmpeg.exe / ffprobe.exe
             │
          deno.exe
```

## Слои

- `models` — неизменяемые `MediaItem`, `DownloadOptions`, `DownloadJob`,
  `PlaylistJob`, `DownloadProgress` и настройки;
- `downloader` — чистая сборка аргументов, JSON-анализ метаданных, разбор
  прогресса и управление процессами;
- `tools` — manifest внешних файлов, контроль версий и SHA-256, безопасная
  установка и обновление;
- `settings` — пути приложения и атомарное сохранение настроек;
- `services` — политики, не относящиеся к виджетам, например частота проверки
  обновлений;
- `ui` — виджеты, форматирование, контроллер и фоновые Qt workers;
- `core` и `utils` — состояние, ошибки, журналирование и маскирование данных.

## Потоки и состояние

Долгие операции выполняются объектами-worker в отдельных `QThread`. Рабочий
поток отправляет только Qt-сигналы; виджеты меняются в главном потоке. Контроллер
удерживает worker и поток до terminal signal, затем освобождает их. Состояния
`IDLE`, `ANALYZING`, `READY`, `DOWNLOADING`, `PAUSING`, `PAUSED`,
`WAITING_FOR_CONNECTION`, `POST_PROCESSING`, `COMPLETED`, `CANCELLED` и `FAILED`
централизованно определяют доступность элементов интерфейса.

Для дочернего процесса stdout и stderr читаются параллельно. Аргументы всегда
передаются массивом, URL отделяется маркером `--`, конфигурация пользователя
yt-dlp игнорируется. При отмене на Windows завершается всё дерево процессов,
чтобы FFmpeg не остался работать в фоне.

## Пауза и восстановление соединения

`DownloadExecutor` сохраняет одно задание и неизменный набор аргументов до
завершения. Кнопки управления вызывают короткие потокобезопасные методы напрямую:
queued slot worker не подходит, потому что его `run` занимает рабочий поток.
`Condition` будит worker при продолжении или отмене без ожидания в GUI.

Во время паузы psutil приостанавливает родительский процесс yt-dlp и его потомков
на Windows. Продолжение возобновляет те же процессы; оно не запускает загрузку
заново. Используются объекты с проверкой идентичности процесса, а не только PID.
При частичной ошибке приостановки уже остановленные процессы возобновляются.
Пауза недоступна во время объединения дорожек и преобразования аудио FFmpeg.
Отмена и явный выход доступны также на паузе и при ожидании соединения.

yt-dlp сначала делает ограниченное число собственных повторов. Если процесс
завершился из-за временной сетевой ошибки, приложение повторяет то же задание
через 5, 10, 20 и затем каждые 30 секунд до успеха или отмены. Проверяется сам
выбранный источник, без запросов к посторонним сайтам. Ошибки авторизации,
удалённые видео, запрет доступа и ошибки диска не запускают бесконечные повторы.
Программа сохраняет `.part` и состояние фрагментов, использует `--continue` и
`--no-overwrites`, не пропускает недоступные фрагменты и останавливает очередь при
ошибке. При повторе готовые файлы/записи архива пропускаются, выбранные интервалы
сохраняются; общий процент не откатывается назад при повторном обходе очереди.

Восстановление зависит от поддержки докачки источником. Для прямого HTTP это
Range, для фрагментированных потоков — состояние yt-dlp. Это не гарантия
восстановления прямых эфиров, удалённых материалов или истёкших авторизаций.
Автосохранение активного задания между запусками приложения не реализовано:
после закрытия нужно снова выбрать ту же ссылку, папку и параметры. Частичные
файлы при отмене или выходе не удаляются.

## Расширение

Новые параметры загрузки добавляются в `DownloadOptions`, затем отражаются в
чистой функции построения аргументов и покрываются тестом. Интервалы плейлиста
разбираются в типизированные значения, объединяются при пересечении и передаются
в yt-dlp одной опцией `--playlist-items`; `PlaylistJob.selected_indices` остаётся
доступен для программного выбора отдельных элементов.
Для обновления самого приложения можно добавить отдельный сервис проверки
GitHub Releases; безопасный self-updater намеренно не реализован.
